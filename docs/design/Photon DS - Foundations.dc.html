Foundations · §00–§11

Architecture, the engine fence, tokens (color · type · spacing · radius · elevation · motion · iconography · touch), the C# token API, and the §10 interaction contract — states, pointer behavior and semantics — that every component spec inherits, and the §11 adaptive layout that decides what a window of each size shows.

◆

Architecture — three layers

one token core · one write-once library · two realizers

Photon is not a standalone system — it is the native realizer of eQuantic.UI. There is one component library, written once; the layers split what is authored once from what each realizer owns. Read the stack bottom-up: the library is authored against the shared core; each realizer turns the same built tree into its runtime — DOM or GPU display list.

Layer 3 · Components — one write-once library authored once in C# · literally the same class on every target
eQuantic.UI.Components — 56 shipped components, authored once against the abstract vocabulary in eQuantic.UI.Primitives (Box · Row/Column · Grid · Stack · ScrollView · Overlay · Anchored · Pressable · Text · TextEntry · Icon · Image …). Not two similar APIs — the same C# class reaches both targets. This doc's Phase A/B/C specs are its contract; anatomy adapts per target from the same class (Select & DatePicker: BottomSheet on touch, anchored popover on pointer).
Web-specific behavior — hover, focus-visible, cursor, right-click — is a realizer concern (§10), not a separate component library. The old two-library world (a ~77-component shadcn-like web lib with CVA class variants) is retired; nothing composes over Layer 2 except this one catalog.

Governing rules
  • One token PR moves both platforms — never fork the Layer 1 core per platform; deltas (elevation richness, touch sizing) are declared as platform overrides, not copies.
  • Presentation divergence is expected and documented per realizer, not smoothed into a lowest-common-denominator component. Same class, same role — target-shaped anatomy.
  • A shared value that stops working on web (a contrast pair, a curve) is a token bug fixed in Layer 1, not a component patch on one side.
  • Hover, cursor, right-click and every other pointer behavior are specified here — §10 plus each spec’s Desktop & pointer note — and implemented by the realizers. There is no separate web component library to document.

Engine constraints — the v1 fence

Normative. A component spec that needs anything from the right column is a spec bug. The renderer draws exactly this:

check_circle Renderer v1 draws
  • Rounded rects — per-corner radii, SDF anti-aliased
  • Borders of uniform width (inside stroke)
  • Linear gradients, 2 stops
  • Images: contain / cover / stretch / 9-slice
  • Box shadows of rrects (offset, blur, spread, color)
  • Clips: rect / rrect · opacity groups
  • Gaussian blur — expensive; overlays & sheets only
  • 2D transforms: translate · scale · rotate
  • Shaped text (HarfBuzz) + color emoji, glyph atlas
  • Scroll containers with native fling physics
cancel Not in v1 — design around it
  • Arbitrary vector paths / inline SVG
  • Dashed or dotted strokes
  • Complex masks, exotic blend modes
  • Generalized backdrop-filter
  • Per-side border widths
  • Conic / multi-stop gradients
  • Charts, maps, rich-text editors (out of catalog)
Icons are never SVG paths at runtime — they are glyphs from a font atlas or pre-rasterized bitmap atlas (§07).

Rules
  • Components consume tokens only; raw hex in component code fails review.
  • Base colors are fills for OnBase text — never use Base as text on Surface (except Link, audited above).
  • Subtle pairs are for tinted containers: banners, badges, chips, icon-button tonal.
  • Disabled is not a color pair: it is a 38% opacity group on the resolved style (§05 · one saveLayer, uniform across variants).
Engine mapping
  • Colors stored sRGB, blended in linear premultiplied (engine color model).
  • Pressed = fill swap on the same rrect — no state-layer compositing cost.
  • Scrim = full-screen alpha rect; blur behind sheets is optional garnish (D4 budget), never required for legibility.
  • Focus ring = second rrect border (outer radius = control radius + 4dp), not a shadow.
Contrast levelsREQUEST · contrast levelsroadmap 2.3

A second resolution axis beside ThemeMode, with two levels. Standard is everything above. More is what the platform asks for when the user turns contrast up: Increase Contrast on Apple, the contrast setting on recent Android, prefers-contrast: more on the web. The theme stays mode-free, and no component asks which level is on.

  • More is one APCA level up from Standard: Muted 60 → 75, Secondary 75 → 90, labels on fills and Subtles 60 → 75, BorderStrong 15 → 30. It never goes below the WCAG 2 targets either: 7:1 for Muted, 9:1 for Secondary, 12:1 for Primary, 3:1 and 4.5:1 for the borders, 7:1 for every pair.
  • Computed, not picked. Each token keeps its OKLCH hue and moves only in lightness. Chroma drops only where the colour would leave sRGB, and Pressed keeps its lightness offset from Base.
  • Measured on the strictest ground: each text figure is the lowest over Background, Surface and SurfaceSubtle.

Hanken Grotesk, bundled · shaped by HarfBuzz, rasterized by FreeType

One bundled family: Hanken Grotesk (OFL — embeddable in the SDK; tall x-height for small mobile sizes; weights 400–800; tnum for data). Bundling one family (D6: FreeType everywhere) means identical pixels on iOS and Android — a golden-harness requirement. System fonts remain available for user content via font discovery, but components default to the bundled family. Glyphs are atlas-rasterized at discrete sizes; the scale below is the whitelist that keeps atlas pressure bounded.

Dynamic Type policy
  • Reading roles (Body, Label, Caption) scale fully with the OS factor, up to ×1.3 tested tier.
  • Display/Heading clamp at ×1.15, Title at ×1.25 — layout titles must not explode.
  • Containers grow with text: control heights are minimums, padding is fixed, text wraps before it truncates (per-component rules state exceptions).
  • Scaled sizes snap to the atlas whitelist (nearest 0.5px step) to bound glyph memory.
Engine notes
  • Runs shaped once, cached by (text, style, width) — reshape only on change.
  • Alpha-mask glyphs at discrete sizes (8–40dp whitelist); no subpixel AA in v1.
  • Color emoji via COLR strikes → color atlas page.
  • Ellipsis is a shaping-time truncation (…), not a shader trick; max-lines supported on all text.
  • Data/code contexts use tnum feature — no separate mono family bundled in v1.

Scripts and directionREQUEST · scripts and directionroadmap 3.3
  • A role's line height is a minimum. A line grows to fit the tallest face it uses, so a fallback font for Thai, Devanagari or Vietnamese marks never clips. It is measured per line, so Latin text keeps the rhythm of the scale.
  • Direction does not exist in the SDK yet. The request is a direction on the context, set by the culture. Row order, padding and alignment read Start and End instead of left and right, and the specs that already say "mirrors in RTL", like the Drawer, then hold.
  • Directional icons mirror. The icon catalog marks arrows, chevrons, back and send as directional, and the realizer flips them under right-to-left. Glyphs whose meaning has its own direction, such as a clock, a checkmark or media play, stay as drawn.
  • Mixed text inside a line follows the Unicode bidirectional algorithm. Numbers and code stay left-to-right.
When it ships. Goldens per script (Latin, Arabic, Devanagari, Thai, CJK) and per direction hold it, and the status entry flips when a layout direction appears in the Primitives API.

Photon has no margin property. Spacing is owned by parents — Gap between children, Padding inside containers. This keeps the layout pass simple (no margin collapsing) and specs unambiguous.

Corner profileDECIDED · REQUEST · continuous cornersroadmap 3.5 · decided 2026-09-23
  • Native draws the continuous profile. The radius values above stay as they are; what changes is the curve between the straight edge and the arc, which eases in the way Apple's corners do instead of meeting the arc at a hard change of curvature. It applies on macOS, iOS, Android and Windows alike. The curve takes the name of what it is, a superellipse, as Flutter's RoundedSuperellipseBorder does.
  • The web draws it where the browser can. CSS corner-shape draws the same superellipse (Chromium 139+), so the web takes it as a progressive enhancement, and a browser without it keeps the circular corner. The difference between two readers is their browser, not the target. Goldens are per target, and the parity suites compare geometry, not corner curvature. Decided 2026-09-26 (#346).
  • Full stays a stadium. Radius.Full is clamped to half the short side, and a pill keeps round ends in both profiles.
When it ships. Suggested: a corner profile on the theme (CornerProfile.Circular and Continuous), read by the rounded-rectangle signed distance on native. Goldens per native target hold it at every radius step, and the status entry flips when the profile appears in the Primitives API.

Spec format
ShadowSpec(OffsetY, Blur, Spread, Color) — shadow color is #0F1720 in light and pure black in dark, at explicit alpha pairs per level — 0.10/0.45 · 0.12/0.48 · 0.16/0.52 · 0.20/0.56 · 0.26/0.62. Dark is not a flat offset from light; never derive it. Exactly one shadow per node — stacked shadow tricks are a spec violation.
Dark-mode rule
Shadows alone don't separate dark surfaces. Levels E1–E2 additionally require a 1dp Border in dark mode (the doc cards you're reading do this). E3+ keep shadow only — their offset reads clearly.

Spring roles REQUEST · spring roles what replaces the Release glide · roadmap 2.1

A spring starts from the velocity the gesture had at release, so a flick and a slow drag land differently, and a release that gets interrupted continues from where the element is, at the speed it has. The glide can do neither: it always starts at rest and always takes 200ms, reaching 99% at 188ms.

  • Roles, never raw numbers. With mass 1, stiffness k = (2π ÷ response)² and damping c = 4π·ζ ÷ response, so a role is two perceptual numbers: how quickly it responds and how much it rings.
  • Velocity in. The initial velocity is the gesture's at release, in dp/s. The target is picked by position and velocity, the way the glide picks it today.
  • At rest within 0.25dp of the target and below 5dp/s; then it lands exactly on the target. The times in the table use that rule.
  • Interruptible. A touch on a moving element takes its current position and velocity, so nothing jumps.
  • No bounce. Both roles damp at ζ ≈ 0.9, so the overshoot stays under 0.4% even when flung at four travels a second. Bounce is not part of Photon's motion.
  • Outside the duration scale. A spring has no duration, so 100 / 200 / 300 does not govern it. The scale stays for keyframed motion, and Enter and Exit keep their beziers.
  • Reduce Motion: the release goes to its target with the 120ms crossfade, like every other movement.
  • Web: the runtime steps the same integrator for pointer drags. CSS transitions keep the bezier roles.
