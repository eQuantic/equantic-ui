Photon Mobile
Design System

The component specification for eQuantic.UI Native — sibling of the eQuantic.UI web library (conceptual parity: same variant & size vocabulary), rebuilt for mobile on a proprietary GPU renderer. Every visual in this document is drawn inside the v1 engine fence: rounded rects, uniform borders, 2-stop linear gradients, rrect shadows, glyph-atlas icons and shaped text — nothing else.

00

Engine constraints — the v1 fence

Normative. A component spec that needs anything from the right column is a spec bug. The renderer draws exactly this:

check_circle Renderer v1 draws
  • Rounded rects — per-corner radii, SDF anti-aliased
  • Borders of uniform width (inside stroke)
  • Linear gradients, 2 stops
  • Images: contain / cover / stretch / 9-slice
  • Box shadows of rrects (offset, blur, spread, color)
  • Clips: rect / rrect · opacity groups
  • Gaussian blur — expensive; overlays & sheets only
  • 2D transforms: translate · scale · rotate
  • Shaped text (HarfBuzz) + color emoji, glyph atlas
  • Scroll containers with native fling physics
cancel Not in v1 — design around it
  • Arbitrary vector paths / inline SVG
  • Dashed or dotted strokes
  • Complex masks, exotic blend modes
  • Generalized backdrop-filter
  • Per-side border widths
  • Conic / multi-stop gradients
  • Charts, maps, rich-text editors (out of catalog)
Icons are never SVG paths at runtime — they are glyphs from a font atlas or pre-rasterized bitmap atlas (§07).

Rules
  • Components consume tokens only; raw hex in widget code fails review.
  • Base colors are fills for OnBase text — never use Base as text on Surface (except Link, audited above).
  • Subtle pairs are for tinted containers: banners, badges, chips, icon-button tonal.
  • Disabled is not a color pair: it is a 38% opacity group on the resolved style (§05 · one saveLayer, uniform across variants).
Engine mapping
  • Colors stored sRGB, blended in linear premultiplied (engine color model).
  • Pressed = fill swap on the same rrect — no state-layer compositing cost.
  • Scrim = full-screen alpha rect; blur behind sheets is optional garnish (D4 budget), never required for legibility.
  • Focus ring = second rrect border (outer radius = control radius + 4dp), not a shadow.

Typography

Hanken Grotesk, bundled · shaped by HarfBuzz, rasterized by FreeType

One bundled family: Hanken Grotesk (OFL — embeddable in the SDK; tall x-height for small mobile sizes; weights 400–800; tnum for data). Bundling one family (D6: FreeType everywhere) means identical pixels on iOS and Android — a golden-harness requirement. System fonts remain available for user content via font discovery, but components default to the bundled family. Glyphs are atlas-rasterized at discrete sizes; the scale below is the whitelist that keeps atlas pressure bounded.

Dynamic Type policy
  • Reading roles (Body, Label, Caption) scale fully with the OS factor, up to ×1.3 tested tier.
  • Display/Heading clamp at ×1.15, Title at ×1.25 — layout titles must not explode.
  • Containers grow with text: control heights are minimums, padding is fixed, text wraps before it truncates (per-component rules state exceptions).
  • Scaled sizes snap to the atlas whitelist (nearest 0.5px step) to bound glyph memory.
Engine notes
  • Runs shaped once, cached by (text, style, width) — reshape only on change.
  • Alpha-mask glyphs at discrete sizes (8–40dp whitelist); no subpixel AA in v1.
  • Color emoji via COLR strikes → color atlas page.
  • Ellipsis is a shaping-time truncation (…), not a shader trick; max-lines supported on all text.
  • Data/code contexts use tnum feature — no separate mono family bundled in v1.

Spacing

4dp base · gap-owned, margin-free layout

Photon has no margin property. Spacing is owned by parents — Gap between children, Padding inside containers. This keeps the layout pass simple (no margin collapsing) and specs unambiguous.

Off-scale values require a token PR — components may not hardcode dp. Odd optical corrections (e.g. icon nudge 1–2dp) are allowed only inside a component's own spec, documented per part.

Spec format
ShadowSpec(OffsetY, Blur, Spread, Color) — shadow color is #0F1720 at the listed alpha in light; pure black at alpha +35pts in dark (shadows must fight darker canvases). Exactly one shadow per node — stacked shadow tricks are a spec violation.

Shadows alone don't separate dark surfaces. Levels E1–E2 additionally require a 1dp Border in dark mode (the doc cards you're reading do this). E3+ keep shadow only — their offset reads clearly.

07

Iconography

glyphs through the text pipeline — never SVG paths
Strategy
  • Ship an icon font built from the Lucide set (outline, 2dp stroke, 24 grid) — glyphs ride the existing FreeType → alpha-atlas path. Zero new pipelines.
  • Rasterized per density bucket (@1x @2x @3x) at the four canonical sizes — no runtime scaling of glyph bitmaps beyond the whitelist.
  • Two-tone / filled states (e.g. active tab) = the font's filled variant glyph, not a layered path.
  • Product-specific art (logos, illustrations) = bitmap atlas via Image (9-slice capable), pre-rasterized per density at build time by the SDK.
  • This document previews icons with a stand-in ligature font (Material Symbols Rounded); metrics and usage rules are identical.

Touch targets & safe areas

Hit-slop model
Small · 32
48×48 hit
Every interactive node exposes a hit rect ≥ 44pt iOS / 48dp Android (engine uses 48dp both — the stricter). Visual bounds may be smaller; the framework auto-expands hit-slop symmetrically and asserts in debug when overlapping hit rects fight.
  • Adjacent small controls (icon rows): hit rects split the gap midpoint, never overlap.
  • Row-level targets (ListItem) absorb their children unless a child is independently interactive (trailing Switch).
Safe-area insets
content
area
  • Insets come from the platform shell each frame (rotation-safe).
  • SafeArea pads; edge components (AppBar, BottomNav, Sheet) extend their background under the inset and pad content — no letterboxing.
  • Scroll content: bottom inset added to content padding, so the last row clears the home indicator.

typed structs — allocation-free, AOT-safe, no CSS anywhere

public readonly record struct ColorToken(Rgba Light, Rgba Dark);
public readonly record struct VariantColors(ColorToken Base, ColorToken OnBase, ColorToken Pressed, ColorToken Subtle, ColorToken OnSubtle);

public readonly record struct ShadowSpec(float OffsetY, float Blur, float Spread, ColorToken Color);
public readonly record struct MotionSpec(int Ms, Curve Curve);          // Curve.Standard | .Decelerate | .Accelerate | Curve.Spring(380, 34, 1)

public enum Variant { Primary, Secondary, Destructive, Outline, Ghost, Link, Success, Warning, Info }
public enum Size    { Small, Medium, Large, XLarge }                    // control heights: 32 · 40 · 48 · 56 dp

public static class Space  { const float S1=4, S2=8, S3=12, S4=16, S5=20, S6=24, S8=32, S10=40, S12=48, S16=64; }
public static class Radius { const float Xs=4, Sm=6, Md=10, Lg=14, Xl=20, Full=999; }

public interface IAppTheme
{
    ColorToken Background { get; }  ColorToken Surface { get; }  ColorToken SurfaceSubtle { get; }
    ColorToken Border { get; }      ColorToken TextPrimary { get; } /* … */
    VariantColors Colors(Variant v);                 // Outline/Ghost/Link derive from Text + Border + SurfaceSubtle
    TypeStyle Type(TypeRole role);                    // Display, Heading, Title, BodyL, BodyM, Label, Caption
    ShadowSpec Elevation(int level);                  // 0–5
}

new Box(style: BoxStyle, child: Widget?)

The atom. A Box is the engine's rrect surfaced as a widget: 1 fill draw + optional border draw + optional shadow draw. Every visible surface in the system decomposes into Boxes.

Anatomy

② border · uniform
① child + padding

EdgeInsets of Space tokens. No margin exists — outer space belongs to the parent's Gap/Padding.

A5

SafeArea

new SafeArea(edges: Edges.All, minimum: EdgeInsets.Zero, child: ...)
Behavior
  • Pads its child by the platform insets (notch, home indicator, status bar, display cutouts) on the selected edges.
  • minimum merges via max(inset, minimum) — gutters never collapse to zero on rectangular screens.
  • Consumption: a SafeArea zeroes the inset for its subtree — nested SafeAreas never double-pad.
  • Insets update per-frame from the shell: rotation, in-call status bar, foldable posture.
Usage
  • Wrap screen content, not edge components — AppBar, BottomNavigation and BottomSheet handle their own insets (they paint under the inset and pad inside; §08).
  • Don't wrap ScrollView in a bottom SafeArea — pass the inset as content padding instead so content scrolls under the home indicator but rests clear of it.
  • A11y: transparent.
A6

ScrollView

new ScrollView(axis: Axis.Vertical, child: ...) — bounded content only; virtualized lists are List (B2)
Aspect
Spec
Physics
Platform-native curves. iOS: exponential decay (normal rate 0.998) + rubber-band overscroll. Android: fling friction + stretch overscroll (scale transform — inside the fence; no glow arc).
Gesture
Drag slop 8dp before capture; captures from pressed children (press cancels into scroll). Release injects gesture velocity into fling. Tap during deceleration stops dead, second tap interacts.
Scrollbar
3dp pill, Radius.Full, BorderStrong @ 60%, 2dp from edge. Appears on scroll, fades out 800ms after idle (Fast/Base motion). Non-interactive in v1.
Insets
contentPadding merges safe-area bottom (§A5). Keyboard: bottom inset grows by IME height; focused input kept visible (M4).
Nesting
Cross-axis nesting fine (horizontal carousel in vertical page). Same-axis nesting asserts in debug — restructure with List sections.
Engine path
Scroll = translated rrect clip. The compositor caches the content layer; a scroll frame re-encodes zero widgets — it updates one transform. 120Hz fling is a translate-only frame well inside the 8.33ms budget.
A11y
Exposed as a scrollable region; VoiceOver 3-finger / TalkBack 2-finger swipes page by 80% viewport and announce "Page X of Y" when paging is enabled. Offscreen children stay in the semantics tree (readers scroll them in).

A9

Heading · Label

new Heading("Portfolio", level: 1) · new Label("Email", target: emailInput)
Heading — semantic Text
  • Level 1 → Heading role, 2 → Title, 3 → Label-strong. Visual role can be overridden; semantics can't.
  • Announced as "heading, level N" — VoiceOver rotor / TalkBack heading navigation jump between them.
  • Exactly one level-1 per screen (debug assert). Never pick Heading for its looks — that's Text(role:).
Label — control caption
  • Label role type (13/16/600), TextSecondary by default; 6dp gap above its control.
  • target: binds it as the control's accessible name — the reader speaks "Email, edit text" focusing the input, and the label itself is skipped.
  • Tapping a Label forwards the press to its target (extends the hit area upward).

Rules
