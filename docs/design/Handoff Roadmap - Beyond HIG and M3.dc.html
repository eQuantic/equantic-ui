Beyond HIG and Material 3

Apple and Google publish guidance, and their toolkits are the implementation. Material goes further than Apple: its tokens are generated into Compose and Web. What neither does is fail a build when a published page, a token and the shipped control disagree, in both directions, across five targets. That is the bar this proposal sets. It has three tiers: finish making the spec executable, close the gaps where both platforms are ahead today, then go past them where a single write-once core allows it.

TIER 1

Finish making the spec executable

This is the lead neither platform has, and it has four holes. Each one is a place where a number or a status can still drift without a test noticing.

PREPARED The patch for all of Tier 1 is in handoff-tier1/: three new tests, status.json, tokens.json 1.3.0, the 35 page edits in edits/pages.edits.json and the Tokens.cs comment fixes. APPLY.md says what to copy, delete and run.
1.1Generate the C# view, or delete it
Tokens.handoff.cs is not compiled and nothing compares it, so it has already drifted. Motion.ExitFor returns MotionSpec there and int in the SDK. The Avatar, selection and wheel members are missing, and Space.Gutter means a column gap there and a screen inset in the SDK.
Pinned by: generating it the way design-system.generated.ts already is.
1.2Pin what the SDK adds
The pin only asks about keys it lists. The switch track (52×32, 44×26), knob, selection box, radio dot, avatar sides and Touch.WheelLine ship in the SDK but are not in tokens.json, so nothing holds them.
Pinned by: reflecting over Sizing and Touch; any public member not published and not exempted fails.
1.3Pin the numbers printed on the pages
The phase pages repeat figures in prose, like "44×44 day cells" or "thumb 24dp". That is a second copy outside the pin. Mark each derived figure with its token path and let a test compare the text.
<span data-token="controlMetrics.small.height">32</span>
Pinned by: a figure test beside HandoffVocabularyTests.
1.4Derive status instead of typing it
C16 still said NOT YET IN SDK and every footer called C15 a request, while both ship. VariantColors.Hover and the SemanticNode state fields had shipped too, and twenty table rows still called them requests. BottomSheet.cs and Toast.cs cite the old C3/C4 numbering. A status.json per block (shipped, partial, request) removes the hand-typed badge.
Pinned by: checking each "shipped" block against the component type existing.
1.5Both settledDECIDED
Springs, settled. No code reads SpringSpec: releases glide over 200ms with smoothstep in DragStore. So tokens.json was right and the SDK's comments were wrong, and the patch corrects the comments. Shipping the behaviour is 2.1.
Compact hit target, decided. Pointer exception: under a pointer a target is its own visual bounds, on a finger it is at least 48dp. Foundations §08 →
TIER 2

Close the gaps where both platforms lead

Each card states what Apple and Google ship, what eQuantic adds on top, and the test that holds it. Names are suggestions until the SDK has them.

SPECIFIED All six are written into the Foundations page as REQUEST blocks, ahead of the SDK. The values they propose live in proposals.json, outside the pinned tokens.json, and status.json tracks each one until its API appears.
2.1Physical motionSPECIFIED · REQUEST
Today: SwiftUI animates with springs by default, and M3 Expressive moved to spring physics.
Add: spring roles over the shipped SpringSpec, with the release velocity injected on every gesture. The 200ms smoothstep glide retires, and the web runtime steps the same integrator for pointer drags. The bezier roles stay for keyframed motion.
Pinned by: comparing the integrator with the closed-form spring within 0.25dp, and goldens of a sheet release.
Spec · Foundations §06 · Spring roles →
2.2The rest of the adaptive setSPECIFIED · REQUEST
Today: M3 has five window classes, breaking at 600, 840, 1200 and 1600, and three canonical layouts: list-detail, supporting pane and feed. eQuantic already ships the first three classes (WindowSizeClass at 600 and 840), AdaptiveNode, whose branches the web emits behind build-time media queries, and ListDetail. NavigationRail swaps with the bar inside an AdaptiveNode.
Add: the Large and Extra-large classes, so a wide desktop window can hold a pinned Drawer and a third pane, and supporting pane and feed as components beside ListDetail.
Pinned by: one golden per class for each canonical layout.
Spec · Foundations §11 · Adaptive layout →
2.3Contrast levelsSPECIFIED · REQUEST
Today: iOS has Increase Contrast. M3 generates standard, medium and high contrast schemes.
Add: contrast as a second resolution axis next to ThemeMode, keeping the theme mode-free. The web emits it under @media (prefers-contrast: more), and native reads the OS setting at paint. Borders and muted text step up, and every pair is recomputed at the stricter level.
Pinned by: DesignTokenTests, run once per contrast level instead of once.
Spec · Foundations §01 · Contrast levels →
2.4Tonal surfaces and a dragged stateSPECIFIED · REQUEST
Today: M3 raises a surface by tone, from container lowest to highest, and gives dragged its own state layer.
Add: a five-step surface ladder so that in dark mode depth reads by tone, where a shadow is nearly invisible. The single rrect shadow stays. Dragged joins the eight states as a derived value, the way hover already is, with no sixth tuple slot.
Pinned by: tokens.json and HandoffTokenPinTests, like every other surface.
Spec · Foundations §05 · Tonal surfaces →
2.5Type that scales like Dynamic TypeSPECIFIED · REQUEST
Today: Dynamic Type has twelve steps, including accessibility sizes, and large styles grow less than body text.
Add: a scale curve per role in place of one MaxScale clamp. Display stops early, Body keeps growing into the accessibility sizes. Layouts that cannot fit switch mode at those sizes: rows stack and trailing values move under the title.
Pinned by: goldens at 100%, 130% and the largest accessibility size.
Spec · Foundations §02 · Type scaling →
2.6Haptics as tokensSPECIFIED · REQUEST
Today: iOS offers impact, notification and selection feedback. Android documents haptics per interaction.
Add: named haptic roles (selection tick, snap, success, warning, error) that components fire on their existing moments: Slider detents, Stepper repeat, sheet snap, swipe commit. A host with no haptics resolves them to nothing, the same rule capabilities follow.
Pinned by: a recorded haptic trace per component interaction test.
Spec · Foundations §08 · Haptics →
TIER 3

Go past them

Apple owns one platform and Google ships a library per platform, so neither can test a promise across all of them. One component tree can.

SPECIFIED 3.1 to 3.3 are REQUEST blocks on Foundations and the Handoff page. 3.4 and 3.5 were decisions, taken on 23 September: APCA is adopted and the dark palette re-solved, and native draws continuous corners while the web stays circular.
3.1One accessibility contract, five targets
The same target-neutral semantics tree already feeds VoiceOver on macOS and iOS and TalkBack on Android. What no test says yet is that they agree: assert that one component produces the same role, name, state and reading order through ARIA on the web and through each native bridge, and fail the build when one drifts.
Pinned by: a semantics parity fixture, like the existing lowering parity.
Found: the vocabulary names Radio, Tab, MenuItem, Option and Destination, and the native tree announces all five as Button. SemanticRole needs those members first.
Spec · Foundations §10 · One accessibility contract →
3.2The live spec
HIG and M3 show pictures of controls. Each handoff block could render the shipped component instead, compiled by the real eqc the playground already uses, beside its spec. It would link to the pin test and the golden that hold it. A designer then reviews the control users get, not a drawing of it.
Pinned by: the block fails to render when the component's API changes.
Spec · Photon Handoff · Live blocks →
3.3Type that knows the script
Both platforms advise taller lines for scripts like Devanagari, Thai and Arabic, and mirrored layouts for right-to-left. The shaper already knows the script of each run, so line height can adjust per script at shaping time, and directional icons can carry a mirror flag in the icon catalog.
Pinned by: goldens per script and per direction.
Spec · Foundations §02 · Scripts and direction →
3.4Two contrast metrics, both published
tokens.json records WCAG 2 ratios today. Recording the APCA lightness contrast beside each pair would be a second measure that tracks perceived contrast better in dark mode. The build would fail if either drops below its floor.
Pinned by: DesignTokenTests, computing both.
Spec · Foundations §01 · APCA →
Adopted 2026-09-23. The 8 dark pairs under APCA's floors were re-solved, with Secondary lifted too so the tiers stay apart. tokens.json 1.5.0 carries the new values and the SDK follows.
3.5Continuous cornersDECIDED · NATIVE
Apple draws continuous-curvature corners and Material draws circular ones. Photon's signed-distance model could offer a continuous profile as a corner style, rendered identically on every native target and held by the goldens. On the web it needs a mask or a CSS corner-shape property that is not yet reliable everywhere, so it would stay fenced there until it is. Worth doing only if you want that Apple look on Android and Windows too.
Spec · Foundations §04 · Corner profile →
ORDER

Order of attack

1
Tier 1, all five. Cheap, and it stops drift before new tokens arrive. Every later item adds numbers, and each one needs somewhere pinned to land.
2
2.1 springs, then 2.3 contrast, then 2.2. Springs are the gap a user feels first. Contrast levels are an accessibility gap. The two larger window classes matter once desktop windows get wide.
3
3.1, the accessibility contract. The bridges already exist on macOS, iOS and Android, so what remains is the proof: the same tree, shown equal on every target. It is the claim neither platform can make.
4
2.4 to 2.6, then 3.2 to 3.4. Each is independent. The live spec in 3.2 is the one to show outside the team, because it turns the handoff itself into the demo. 3.5 waits on your call.
