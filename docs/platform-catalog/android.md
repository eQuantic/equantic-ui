# Android developer capability catalog: Android 16 (API 36), Android 17 (API 37), Jetpack, Google Play services and Google SDKs

As of 2026-10-11. Written for a .NET UI SDK whose native track runs C# through .NET for Android (`net10.0-android`) Java bindings.

The catalog keeps Google's own names, "widget" included, where it names what Google ships or cites it: such a name is Google's product, never an eQuantic.UI component.

## Release facts (verified)

- **Android 16 (API 36, "Baklava")** shipped in June 2025. **Android 16 QPR2 (API 36.1, `BAKLAVA_1`)** shipped on 2 December 2025. It was the first release to use a *minor SDK* version, checked with `Build.VERSION.SDK_INT_FULL` / `VERSION_CODES_FULL`.
- **Android 17 (API 37, "Cinnamon Bun", `CINNAMON_BUN`)** shipped on **16 June 2026**, according to the Android Developers Blog post "Android 17 is here".
- **Android 17 QPR1 = API 37.1 (`CINNAMON_BUN_1`)**. Its API diff was generated on 2026-06-29, and it reached users around September 2026.
- **Android 17 QPR2 = API 37.2 (`CINNAMON_BUN_2`)** is **still in beta** (Beta 7 was published in October 2026). Its API diff was generated on 2026-08-28. Rows marked 37.2 are pre-release.
- **.NET binding level.** NuGet shows that the stable .NET 10 Android workload ships `Microsoft.Android.Ref.36` / `.36.1` (36.1.x). **API 37 bindings exist only as `Microsoft.Android.Ref.37` 37.0.0-rc.1, which is .NET 11 pre-release.** So in `net10.0-android`, no API 37+ platform type is bound. Reaching one means hand-written JNI, or waiting for .NET 11 (`net11.0-android37`).

## Legend

**Layer**
- `platform` = an `android.*` framework API.
- `jetpack` = AndroidX.
- `play-services` = `com.google.android.gms` / `com.google.android.play`, or an ML Kit *unbundled* model. Needs Google Play services or the Play Store on the device.
- `google-sdk` = a Google SDK bundled in the APK: ML Kit bundled, Firebase, MediaPipe, LiteRT, ARCore client, Home APIs, ADK.

**Reachability from C#** (more than one tag may apply)
- `java`: a plain Java-callable shape that binds cleanly.
- `kotlin-only (…)`: binds badly or not at all, with the reason given:
  - `suspend`: surfaces as a method with a trailing `IContinuation`.
  - `Flow`: must implement `FlowCollector`.
  - `Compose`: `@Composable` needs the Compose compiler plugin, so it is unusable from C#.
  - `KSP` / annotation processor: the codegen never runs over C# types.
  - `defaults`: Kotlin default params or a DSL.
  - `value-class`: name-mangled members that the binder skips.
- `play-services`: absent on Huawei, Amazon and AOSP devices.
- `policy (…)`: a restricted permission or a Play Console declaration.
- `separate-process`: rendered or run by the system or a host, outside the app's activity (a Home Screen surface, tile, complication, service bound by the OS).

**New** marks: `NEW 16` = API 36, `NEW 16-QPR2` = 36.1, `NEW 17` = API 37, `NEW 17-QPR1` = 37.1, `NEW 17-QPR2` = 37.2 (beta).

**Platform binding**
- `Mono.Android` = present in `net10.0-android` (API ≤ 36.1).
- `MA-37 (.NET 11 only)` = API 37 types exist only in the `Microsoft.Android.Ref.37` 37.0.0-rc.1 pre-release.
- `none (37.x)` = minor SDK 37.1/37.2, not bound anywhere yet (unverified).

**Jetpack / GMS binding**
- The NuGet id comes from dotnet/android-libraries `config.json`, with the bound version in parentheses where it lags the upstream version.
- "community" = not Microsoft.

- **eQuantic**: what covers the row on `main` today, or the issue that owes it. ✅ a contract realized on this platform, ⚠️ realized with a limit that matters, 🐛 a bug that blocks it; an issue number alone is work owed under [#774](https://github.com/eQuantic/equantic-ui/issues/774). Empty where nothing is planned yet. Added on 2026-10-11 from `Primitives/Devices` and each shell's `*Capabilities.cs`.

## Notes for the C# SDK

- **The binding gap is the biggest constraint.** Every row tagged `MA-37 (.NET 11 only)` or `none (37.x)` is unreachable from `net10.0-android` without hand-written JNI. That covers the Android 17 contact picker, eyedropper, Handoff, location button, Notification.MetricStyle, AppFunctions runtime registration, NPU and serial / HID APIs, and the 17-QPR2 agent APIs.
- **Kotlin-shaped libraries.** Compose-only surfaces (Glance, Remote Compose, Media3 UI Compose, Wear Compose, XR, A2UI, CameraX Compose) and KSP-driven ones (Room, AppFunctions Jetpack, genai-schema, firebase-ai typed schemas) need a different strategy. That means the platform equivalent (RemoteViews, AppFunctionService, SQLite) or a Kotlin shim compiled into an AAR and bound.
- **Stale Microsoft bindings.** ML Kit GenAI Prompt (alpha1 vs beta4), Pose detection (17.0.0 vs 18.0.0-beta5), Biometric (1.1.0 vs 1.4.0-alpha07), Firebase Messaging (25.1.3 vs 26.0.0), Sign in with Google (1.1.0 vs 1.2.1), Play AI Delivery (alpha01 vs beta01), LiteRT (2.1.5 vs 2.3.0), Firebase App Check (19.4.1 vs 20.0.0). ARCore's Microsoft package (1.29.0) is no longer in android-libraries at all.
- **No binding at all.** None of the ML Kit GenAI feature APIs except Prompt, Firebase AI Logic (community only), firebase-ai-ondevice, LiteRT-LM, AppFunctions Jetpack, Glance, Health Services, UWB, Core Telecom, Engage, Watch Face Push, ML Kit entity extraction, selfie / subject segmentation and face mesh, Media Enhancement / Studio Sound, Home APIs, Navigation SDK, or any Jetpack XR library.
