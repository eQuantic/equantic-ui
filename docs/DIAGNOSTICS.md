# Diagnostics

Every build error and warning eqc can print, with what it means and what to do about it. The
codes are stable: they are what you search for, and what a suppression would name.

A guard keeps this page honest — `DiagnosticsDocumentedTests` fails the build when a code is
reported from `src/` and has no row here, when a row names a code that no longer exists, or when
a code gains a new reporting site. The last one is not a style rule: **EQ2101 was once two
unrelated errors** (a resx translation mismatch and `System.IO` in a client component), each
pinned by its own green test, because the two never met in one compilation.

Diagnostics print in MSBuild-canonical form, so the IDE and `dotnet build` both link them:

```text
Pages/Counter.cs(14,9): error EQ2002: C# 'goto' cannot be transpiled to JavaScript …
```

## EQ0xxx — the build host

The `eqc` process itself, before or around a compilation.

| Code | Meaning | What to do |
|---|---|---|
| `EQ0000` | A compilation error arrived with no code of its own. | Read the message — the code is missing, not the diagnosis. |
| `EQ0001` | eqc crashed. | A bug in the compiler. The message carries the exception; please report it with the source that triggered it. |
| `EQ0002` | The MSBuild reference list is empty, so the semantic model would be built from an incomplete compilation and named arguments could be emitted in the wrong order. | Rebuild (`dotnet build`). If it persists, `CompileEQuanticUI` ran without `FindReferenceAssembliesForReferences`. |

## EQ1xxx — no translation exists yet

A gap in the compiler, not in your code. The construct is legal C# and could be translated; today
nothing does it. These are the codes that shrink as the compiler grows.

| Code | Meaning | What to do |
|---|---|---|
| `EQ1001` | A C# **expression** kind has no transpilation strategy. | Rewrite it in a transpilable form, or add a conversion strategy for the construct. |
| `EQ1002` | A C# **statement** kind has no transpilation strategy. | As above. |
| `EQ1003` | A C# **node** (neither expression nor statement) has no strategy. | As above. |
| `EQ1004` | A strategy **matched** the construct but this exact form has no emission — the translation would be silently wrong, so it stops. | Rewrite the form, or add the missing case to the strategy. |
| `EQ1005` | Two types share a twin filename — either the same name twice, or two names that differ only in case (one file on Windows and macOS). Their twins would be ONE file and the second would overwrite the first. | Rename one of the types. |
| `EQ1006` | *(warning)* One type is declared in more than one place and eqc emits one module per declaration, so the twin holds only the first declaration's members. | Combine them into a single declaration, or keep the members a component uses together in one. Harmless when the other halves are server-only, which is why it does not stop the build. |
| `EQ1007` | A method name declared twice in one type: two overloads, or two names that lower to one (`Foo` and `foo`). C# tells overloads apart by their parameters, and a JavaScript class has one member per name, so the twin would keep one of them and every call would reach it: a class, a record or a static class kept the LAST, a component the FIRST, all in silence. A static and an instance method may share a name, a partial method's two halves are one method, and an explicit interface implementation takes the interface's name, which no rename can change, so the overload check leaves it out and judges it by what else holds that name (below); beside a default of another interface it takes its member's name like any member, and is checked. Two defaults a class takes from different interfaces, or a default and a member the class declares, land on one name the same way, and so do the same pairs along the class chain: a member a derived class declares on the name of a default its base takes (unless it implements that default's interface member, the class listing the interface again), a default on the name of a member a base declares, and two defaults of different interface members, one taken by a base and one by the derived class. An INDEXER takes two names on its twin, `item` for its getter and `setItem` for its setter (#427), so a second indexer, or any member the twin holds on those names (a method, a field, a property, an event, a primary constructor's parameter a member reads) lands on the same member and is refused, the message naming what to rename. An explicit implementation of an interface's indexer holds `item` and `setItem`, which every access through the interface reaches, and the type's own indexer beside it takes names of its own (`Grid$item`); what an access through an interface cannot tell apart, two explicit implementations or one beside an indexer or a default that answers another interface, is refused. A RECORD's or a STRUCT's instance members that land on one name are refused too: its twin holds the state of each instance as properties of its own and its methods and computed properties on its prototype, so two of them shared one slot (`struct S(int x) { public int X { get; } = x * 2; }` answered `6|6` for `3|6`) or the constructor wrote one over the other (`readonly struct Money(decimal amount) { public decimal Amount => amount; }` threw at `new`). A member the body declares under a positional parameter's own name is that parameter's property, one member, and a primary constructor's parameter read only by an initializer is held by no instance. A plain CLASS holds a primary constructor's parameter that a member reads the same way (#583), so one that lands on another member's name is refused: `class Greeter(string name) { public string Name => name.ToUpper(); }` would answer the parameter for `Name`. Two parameters of a primary constructor that land on one name (`x` beside `X`) are refused on a class, a record and a struct alike: the twin's constructor names them camelCased, and a function cannot take two parameters of one name. A method that HIDES an inherited member, with `new` or with the same signature and no `override`, is no second method: its twin holds it under a name of its own (`name$1`), and a call bound to the hidden member keeps reaching it, so it is not refused (#563); one that hides a member and answers an interface is, since a call through the interface reaches the hidden member's name. So does a method beside an explicit interface implementation of its name, which holds that name: one that also answers another interface is refused, since a call through that interface would reach the explicit one. An EXPLICIT IMPLEMENTATION that hands back what the member holding its name answers (`string IBar.Run() => ((IFoo)this).Run();`, `string IFoo.Run() => Run();`, `int IVal.Value => Value;`, its parameters passed through as they came, on `this` and through no member a derived type can override on the way, and the value handed back as it was: a number widened to a `long`, a struct boxed into a copy, an `as` or a cast down, and an `out` or a `ref` are no hand-off, and a server action's stub is where one ends) is not written: that member answers every call through each interface, so a method it hands off to keeps its name, and is not refused for answering another interface (#1139). Every other one is written under its member's name, which a call through the interface reaches whatever type implements it, so what else the twin would hold on that name along its chain is refused, where the browser kept one of them in silence (`IFoo.Run()` and `IBar.Run()` both answered as `IBar`'s, and one handing off to the other, written last, called itself until the stack overflowed): two explicit implementations of one name (two interfaces' members, or one interface over two type arguments, static ones too), one beside a property, an event or an override of the type's own, one on the name of a member a base the source declares holds (an abstract method's included, which its overrides fill), unless that is the base's explicit implementation of the same interface member, which the type re-implements, and one on a name the runtime reads of every object, `equals`, `getHashCode` or `toString`. A typed `Equals`, any `Equals` overload but `Equals(object)`, holds a name of its own too (`equals$1`, numbered along the class chain, explicit implementations first), so two of them in one type, or one beside a base's, are not refused, and each call reaches the overload it binds (#947). A SEQUENCE's twin has one iteration and one `current` (#612), so a type that implements `IEnumerable<T>`, or `IEnumerator<T>`, over two types is refused, since LINQ, a spread and a `foreach` over each of them would walk one sequence, and so is a non-generic `GetEnumerator()` or a `Current` the twin holds as one with the member it keeps, where it answers otherwise, which C# allows. One that hands back what that member answers (`IEnumerator IEnumerable.GetEnumerator() => GetEnumerator();`, `object IEnumerator.Current => Current;`) answers alike, and is held as one. | Give each overload its own name, and keep one indexer (`Compare` and `CompareLines`); rename a record's or a struct's member that meets another (a private field `_amount`, a primary constructor's parameter by what it holds), and a class's primary constructor parameter that meets a member, or hold it in a field of your own (`private readonly string _name = name;`). Implement `IEnumerable<T>` over one type and hand another sequence out through a member of its own (`public IEnumerable<string> Names => …`), and return what the member the twin keeps returns from a non-generic `GetEnumerator()` or a `Current`, through it. Have an explicit implementation hand back what the member it meets answers where the two answer alike (`string IBar.Run() => ((IFoo)this).Run();`), or give one of the interfaces' members a name of its own. The bound tree says which overload each call binds, so this is a gap the compiler can close by naming overloads apart, as it does user-defined operators. |
| `EQ1008` | A class relies on a default interface member of an interface compiled into a referenced assembly outside the SDK. JavaScript has no interfaces, so eqc writes each default a class takes into its twin: converted from the interface's source when the compilation has it, and delegated to the runtime's copy for the SDK's own interfaces (`IAppTheme`, `ICodeLanguage`, `ICodeCompletionProvider`), the public interfaces of the assemblies the runtime provides. Any other assembly's interface has neither, whatever namespace it declares, so the twin has no such member and a call to it in the browser would meet undefined. The same for a default that uses a static member of an interface, which has no JavaScript form to hold it. | Declare the member in the class, or keep the class out of client code. |
| `EQ1009` | A record's, a struct's or a plain class's constructor its twin cannot reach. A JavaScript class has one constructor, so its twin takes a branch per C# constructor on how many arguments arrived, its optional parameters counted (#413, a plain class's since #583): each constructor that does its own work (the primary one, or an explicit one that does not chain with `: this(…)`) binds its parameters, sets the members, calls its base's constructor and runs its body, and each one that chains runs its root after evaluating the chain's arguments. A constructor that takes a count of arguments another one takes too cannot be told from it, and one that chains to a constructor that chains in turn, or `: this()` to a struct's implicit constructor beside constructors of its own, reaches its work through nothing. A record's copy constructor (`protected R(R original)`) is no branch: `new` never reaches it. Nor is the constructor only .NET's serialization calls, `(SerializationInfo, StreamingContext)`, which Visual Studio's exception template writes beside `(string, Exception)`: the browser has no `SerializationInfo`, and an exception class of the app's is a class whose constructors are checked as any class's are (#611). A call of one the browser would make, a `new`, or the `: base(…)`, `: this(…)` or base clause of a constructor the twin writes, is refused, since with no branch for it the call would run another constructor of two arguments (`new Snap(info, context)` ran `Snap(string, string)`); the template's own calls its base's, is no branch, and makes no call. | Give the constructor a count of arguments of its own, or chain it to one that does its own work. A factory (`static Coded FromText(string text) => new(text.Length)`) says the same thing without a second constructor. Build an object whose serialization constructor a call reaches through another of its constructors. |

## EQ2001–EQ2014 — the construct cannot cross

Not a gap: there is no browser equivalent, or a translation would have to be a guess. These do
not shrink with compiler work — they are the shape of the target.

| Code | Meaning | What to do |
|---|---|---|
| `EQ2001` | A C# construct with no runtime equivalent in the browser (typed-reference intrinsics: `__makeref`, `__reftype`, `__refvalue`, `stackalloc`, pointers). | Restructure without it. |
| `EQ2002` | `goto`. | Restructure with loops and conditionals, or a labelled `break`/`continue` (those DO translate). |
| `EQ2003` | `new T()` on a type parameter — generic arguments are erased at runtime in JavaScript, so the concrete type is unknown. | Pass a factory (`Func<T>`) or the constructed value in. |
| `EQ2004` | A member declared outside the compilation that no strategy translates, so nothing emits it: a BCL member with no JavaScript form (`Convert.FromBase64String`, `DateOnly.ParseExact`), a property or a field no value the browser holds carries (`CultureInfo.CurrentCulture.Name`, `Environment.NewLine`, `typeof(T).Name`), a member of a date, a time, an instant or a span that its twin does not carry (`TimeSpan.TryFormat`, `DateTime.ToBinary`, `DateTimeOffset.ToFileTime`), `GetType()` and `MemberwiseClone()` called or taken as a method group, a chain read from one (`x.GetType().Name`) reported once at its root, written qualified or reached bare through `using static` (`WriteLine` under `using static System.Console`), an extension method whose declaring class is not part of this compilation, or a `System.Range` value stored rather than indexed with, or handed to an indexer that takes the `Range` itself (`this[Range r]`). A METHOD GROUP of a member no twin carries is the delegate its call is, so a group whose call has no translation is refused at the group with the call's own message (`Func<string, string, IFormatProvider, TimeSpan> read = TimeSpan.ParseExact`), and so is a group whose method hands a value back through an `out` or a `ref`, and a delegate with such parameters built from another (#839). A PACKAGE's type, from an assembly the build has no source for, has no name in the browser: its static, read, called or reached through `using static`, and a construction of it are refused naming the assembly (`Status.Label`, `new Gauge("a")`), while a value of it the server sends keeps reading its members, and a constant and an enum's member are their values (#822). So is a construction of a .NET type no strategy builds (`new Random()`, `new Stopwatch()`, `new Lazy<int>(…)`), and an interpolation made a `FormattableString` or an `IFormattable` anywhere but `FormattableString.Invariant`, `FormattableString.CurrentCulture` and `string.Create(provider, …)`, since the browser holds the text, not the format and its arguments. A member of an API only a server has (file I/O, networking, OS threading) is never this code: it is the client boundary's (`EQ2102`–`EQ2107`, `EQ2112`), told once at the site. | Use a member that translates (index with the range directly, `text[a..b]`, or give the type a `Length` and a `Slice(int start, int length)`, which a range calls), move the call behind a `[ServerAction]`, or bring the declaring source into the compilation. A package's type is constructed and its statics read in a `[ServerAction]`, or its project is referenced instead, whose types the build compiles. A group with an `out` is called where its value is needed. |
| `EQ2005` | An infinite iterator. Iterators are MATERIALISED into an array, so the loop would run forever instead of yielding lazily. | Give the loop an end (a bound, a `yield break`), or take what you need inside the method. |
| `EQ2006` | The member does not bind in the semantic model, so any translation would be a guess. | Either the code does not compile, or eqc is missing references / generated sources. Never guessed — see [Compiler](https://github.com/equantic/equantic-ui/wiki/Compiler). |
| `EQ2007` | A comparer that changes what a collection considers equal or in order: a collection expression's `with(…)` argument beyond a capacity hint, a comparer handed to a collection's constructor (`new Dictionary<string, T>(StringComparer.OrdinalIgnoreCase)`) or to a LINQ operator that finds its keys or its elements by it (`ToHashSet`, `ToDictionary`, `ToLookup`, `GroupBy`, `Distinct`). The runtime's collections find an element by its type's default equality, and take no other comparer. The default comparers and `StringComparer.Ordinal` ask for exactly that, and pass. A sort or a binary search (`List<T>.Sort`, `Array.Sort`, `BinarySearch`) takes more: the type's default comparer, a `Comparison<T>`, a `StringComparer`'s six, `Comparer<T>.Create` and a comparer the app writes cross, and only a comparer no twin carries (a `StringComparer` made for a culture, a comparer a library compiled) is refused. | Drop the comparer, or normalize the keys yourself (lower-case them on the way in and on every lookup). For a sort, pass a `Comparison<T>`. |
| `EQ2008` | Query syntax using `join`, `let`, a second `from`, or `into` — its C# translation runs through compiler-generated transparent identifiers. Also the fenced initializer forms. | Rewrite in method syntax, where every operator is supported. |
| `EQ2009` | A component is declared more than once in one file (partial declarations). eqc emits one module per declaration and cannot merge them. | Combine the members into a single declaration. |
| `EQ2011` | A member that would take a name the runtime's component already uses. C# keeps a primary-constructor parameter, a field and a property apart, and spells them differently from the runtime's camelCase; JavaScript folds all of it onto `this.<name>`, so the assignment replaces the runtime's member and the page fails only in the browser. The list is read from the live runtime (`core/runtime-members.spec.ts` → `Resources/runtime-members.txt`), never typed. | Rename the member. An `override` is exempt — a component's `Build` is meant to replace the runtime's `build`, and replacing a base member is what one is for — but a plain method is not: `public void Mount() { }` overrides nothing and still emits `mount()` over the runtime's own, so the component never mounts. |
| `EQ2010` | A symbol kept on the HOST, named from client code: a member marked `[ServerOnly]`, whoever declares it; a type of the framework marked `[ServerOnly]`, whose twin the runtime does not ship; or a type of the app, or of a project it references, that the build writes no module for, because it or a class it derives from is `[ServerOnly]` or an attribute, or because it is declared inside such a type (#584). The app's own top-level `[ServerOnly]` class is one (#823). The reference would compile, emit, and fail in the browser, on "does not provide an export named" or on a name nothing defines, while SSR kept answering 200. It is refused however client code reaches it: its name, an alias, `using static`, a method group, a construction, an operator or a conversion its value brings, an extension, a type test, a zero, a member's or a local's annotation, a Server Action's answer or parameter. A `[ServerOnly]` method is met through its CONTRACT too: a call or a method group bound to the interface member it implements, or to the method it overrides, carries no attribute and would reach a member the twin leaves out, so it is refused where its receiver can be the type that keeps the method on the server, naming the method, across the app and the projects it references (#816). A call bound to a method that is not `[ServerOnly]`, a call through `base`, and a contract no client code calls build. A variant interface's receiver can hold the type too: `ISource<object>` holds a `StringSource : ISource<string>`, and `ISink<string>` an `ObjectSink : ISink<object>`, while `ISource<int>` holds neither. A `[ServerOnly]` member is refused as a bare method group as it is through `this.`, and so is an extension block's, which no twin holds either; a `[ServerOnly]` operator or conversion is refused wherever client code applies it, a conversion implicit or spelled as a cast, a compound assignment, a tuple equality, a foreach's element and a deconstruction's part included. So is a `[ServerOnly]` method C# calls for the code without naming it: `Deconstruct` in a deconstruction, `Dispose` in a `using`, and `GetEnumerator`, or the `MoveNext`, `Current` or `Dispose` of the enumerator it answers, wherever a sequence is read, a `foreach`, a spread `[.. xs]` or a LINQ operator (#944). An instance member of a type the build writes no module for is refused where client code reads it off a value, whose position names no type, unless the value's expression holds a refusal already (Copilot's review of #944). A module that would import its twin reports it at the declaration that holds the reference. A position the module writes as nothing is free: a component's field or parameter, annotated `any`, a cast, a `nameof`, a reference type's zero, a type argument of a base list, which no twin writes, a dictionary's key or value type, annotated `any` with the dictionary, and a string literal that holds the name (#945). So is code that never crosses: a `[ServerAction]`'s body, a `[ServerOnly]` member, another `[ServerOnly]` class. A type declared inside an exception class of the app's crosses as that class does (#611), and a component crosses whatever it is marked. | Call it from server code: a `[ServerAction]`, a `[ServerOnly]` class, or a realizer. Never from a component's `Build`. A call through a contract is called from server code too, or the method's `[ServerOnly]` is taken off so it crosses. Unlike `EQ2004` this is a DECISION, not a gap — adding a strategy is not the answer. |
| `EQ2012` | A `[ServerAction]` on an ABSTRACT component. The server registers an action under the name of the CONCRETE component carrying it — `ServerActionRegistry.ScanAssembly` skips abstract types and walks inherited methods — so it serves `Tile/Load` while a stub emitted on the base would invoke `CardBase/Load`. Nothing serves that id and the page gets "action not found", on both sides silently. | Declare the action on the concrete component. An alias is not the answer: the descriptor carries the component TYPE to invoke on, so two children inheriting one action give the base's id two answers — the owner of an inherited action is a decision, not a patch. |
| `EQ2013` | A vocabulary type whose browser half revives the values of a type argument (`ServerTopic<T>`, its parameter marked `[HydratesTypeArgument]`) is built where that argument is, or holds, a type parameter: `static ServerTopic<T> Topic<T>(string name) => new(name)`. JavaScript erases the type there, so the topic would carry no spec and every payload would reach its subscribers unrevived, a decimal or a long as the text the wire writes. | Build the topic where its payload type is concrete, as a static member of the type that declares the app's topics: `static ServerTopic<RoomEvent> Room(string id) => new($"room:{id}")`. |
| `EQ2014` | An exception type is built or tested where a type argument it carries, its own or one of a type it is nested in, is, or holds, a type parameter: `static Exception Of<T>() => new Failed<T>()`, `catch (Failed<T>)`, or `new Missing()` inside the generic class that declares it. An exception carries the types it is, which a typed `catch`, `is` and its name read, and JavaScript erases a type parameter, so the exception would carry, or the test compare, `T` itself: `catch (Failed<int>)` missed what `Of<int>()` threw (#611). It is the erasure that refuses `new T()` (EQ2003) and a topic built over a type parameter (EQ2013). | Build and test an exception where its type arguments are concrete types, and declare an exception class outside a generic type. |

## EQ2100–EQ2101 — resx templates

The localization contract, checked on the build machine rather than when a visitor arrives.

| Code | Meaning | What to do |
|---|---|---|
| `EQ2100` | About **this call**: the template must be a valid composite format whose specifiers are inside the supported subset, and the call must pass every hole it declares. | Fix the argument count, or drop the out-of-subset specifier (alignment such as `{0,10}` is outside v1). |
| `EQ2101` | About the **translations**: every culture's resx is held against the neutral one, which is the arity contract. | Fix the culture's template — a dropped or extra `{n}` fails the build, not the page. |

## EQ2102–EQ2107, EQ2112, EQ2114 — the client/server boundary

Client code reached for an API that only exists on a server, or for a value only the server has. The
bridge is `[ServerAction]`.

Client code is what crosses to the browser, and the build reads that and nothing else (#816): every
member of a component that its module holds, a stateless component's as much as a stateful one's, and
every class, record and static class a page's module reaches. A `[ServerAction]`'s body, a
`[ServerOnly]` member and a `[ServerOnly]` class never cross, so they may use all of these APIs. The
API is told where the code writes it, once a site: a call, a read, a construction, a method group, an
extension. It is the namespace that decides, never a prefix of a type's name, and an exception of these
namespaces is a value the browser builds and tests by name (#611), so a page may throw and catch an
`IOException`.

| Code | Meaning |
|---|---|
| `EQ2102` | Direct database access (`Microsoft.EntityFrameworkCore`, `System.Data`). |
| `EQ2103` | Networking (`System.Net.Http`, `System.Net.Sockets`). |
| `EQ2104` | OS threading and locking (`Thread`, `Monitor`, `Mutex`, `Semaphore` — not `Task`). |
| `EQ2105` | Spawning processes (`System.Diagnostics.Process`). |
| `EQ2106` | Native interop / P-Invoke (`System.Runtime.InteropServices`). |
| `EQ2107` | Runtime IL generation (`System.Reflection.Emit`). |
| `EQ2112` | File-system access (`System.IO`). |
| `EQ2114` | A page uses a value the server's container gave it (a constructor parameter of a class type, or a member the page keeps one in) in a way the build cannot follow: a method called on it, the value passed where the build has no source, converted to text, compared, enumerated, stored in a collection, read through a member a .NET type declares on a value that does not cross whole (the `Count` of a list or a set of objects, a pair's `Value`), read through a type whose member of that name the value's own type hides (`new`), or read while the page is constructed. Such a value crosses to the browser as only what the browser reads of it, so a use the build cannot see would draw something else there. Reported by the source generator, so it shows in the editor. Decide on the server, in `PrefetchAsync` or a `[ServerOnly]` member, and keep the result in a field; or call a `[ServerAction]` when the browser's state is an input. |

`EQ2112` sits apart from its family on purpose: `System.IO` was reported as `EQ2101` until that
code turned out to belong to the resx check above, which the wiki already published. It is not a
numbering slip to tidy back.

## EQ2108–EQ2111 — one meaning per target, or none

The construct translates, but would READ differently on the server and in the browser. Rather
than pick for you, eqc asks.

| Code | Meaning | What to do |
|---|---|---|
| `EQ2108` | A `CultureInfo` the browser cannot follow: formatting (`ToString`, `Convert.ToString`, `string.Format`) crosses `InvariantCulture` and `CurrentCulture`, a builder's `Append` and `AppendLine` with a provider and an interpolation cross only `CurrentCulture` or a null, since the interpolation is formatted in the app's culture, and reading a number (`Parse`/`TryParse` on any numeric type, `Convert.ToInt32` and its siblings of a string, `Convert.ToDecimal` of a string or of a value that may hold one, such as an `object`), reading a date or a time (`Parse`/`TryParse` of `DateTime`, `DateTimeOffset`, `DateOnly`, `TimeOnly` and `TimeSpan`, and `Convert.ToDateTime` of a string or an object) and changing case (`ToUpper` and `ToLower` of a string or a char) `InvariantCulture`, `CurrentCulture` and a null, since the browser reads the page's culture and the invariant one. `Convert.ToBoolean` never consults its provider but C# evaluates it, so it crosses `InvariantCulture`, `CurrentCulture` and a null, which are reads with no effect, and any other provider an app writes, while another `CultureInfo` (`GetCultureInfo(name)`, `new CultureInfo(name)`), which may throw, has no twin to evaluate it. The culture is the property the provider binds to, however it is spelled: a member of another type that is also called `InvariantCulture` is refused, since it may return any culture. | Format with an explicit specifier (`ToString("N2")` follows the app's culture on both targets), or convert and read with the invariant culture. |
| `EQ2111` | `GetService` with no type argument to cross — the registry is keyed by the interface NAME, and there is nothing to key on. | Call the generic overload. |
| `EQ2113` | `ConfigureAwait` is dropped — there is one context to resume on — and dropping it would discard a NON-CONSTANT argument without evaluating it. | Pass a constant, or evaluate the expression into a local first. |

`EQ2110` is no longer reported. It warned that a number read from text with no culture read the
request's culture in C# and the invariant one in the browser; since #1087 the browser reads the
page's culture there, as .NET reads the current one.

## EQ3101–EQ3105 — the source generators

The generated factory surface and form models.

| Code | Meaning |

## EQ4xxx — the SDK build

Raised by the SDK's own MSBuild targets, before or after the compiler runs.

| Code | Meaning | What to do |
|---|---|---|
| `EQ4001` | The eQuantic icon tool — `eqicon`, which writes app icons, the vector and font catalogs, the capability manifest and the macOS bundle — is missing where the SDK looks for it. In a build from the repository's source tree, `eQuantic.UI.Native.Build` did not build before this project: a broken build graph. From a package, the package shipped without `tools/net10.0/eqicon.dll`. | Neither is fixed by building twice. From source, the tool is a `ProjectReference` of every app project, so look at the errors above this one — the tool's own build failed — or at whoever removed the edge. From a package, clear the eQuantic cache (`dotnet msbuild -t:ClearEQuanticCache`), restore again, and report the package version if it persists. |
| `EQ4002` | The eQuantic compiler — `eqc`, which turns the app's components into JavaScript — is missing where the SDK looks for it: in a build from the repository's source tree, `eQuantic.Build` did not build before this project; from a package, the package shipped without `tools/net10.0/eqc.dll`; or an explicit `EqcCliPath` names a file that is not there. This used to be a warning, and a page with no JavaScript. | As EQ4001: not fixed by building twice. From source, read the errors above this one or restore the `ProjectReference`; from a package, clear the eQuantic cache and restore; with an explicit `EqcCliPath`, fix the path. |
| `EQ4003` | *(warning)* The app will be signed with a hardened-runtime exception (`com.apple.security.cs.*` — the family that relaxes a protection the hardened runtime imposes) while the build is not hardened. The key reaches the signature and the system never consults it. The SDK signs with `--options runtime` only when `EQuanticHardenedRuntime` is `true`, so any other non-empty value is an unhardened build — `false`, `off`, and the typo `ture` alike — and the message quotes back what was written. An EMPTY value is an ordinary development build and is never reported. | Set `EQuanticHardenedRuntime=true`, or drop the declaration. Not `EQuanticSigningIdentity`: that turns hardening on only where the property is empty, so it does not answer this. Note what this does NOT mean: the App Sandbox's permissions (`com.apple.security.network.*`, `…files.*`, `…device.*`) answer to `PhotonEntitlements.AppSandbox`, not to the hardened runtime, and an ad-hoc development build honours them — so they are never reported here. |
| `EQ4004` | A program the build started ended with an exit code other than zero and reported no error of its own: `eqc`, `eqicon`, bun, git, or on macOS `codesign`, `ditto`, `notarytool`, `stapler` or `hdiutil`. The message names the program and the arguments it was started with, as MSBuild's `Exec` named its command, except for a call whose command line is not echoed: the notary's, which carries a password. A program that reported its own errors, eqc's EQ codes for one, gets no EQ4004 after them. | Run the command the message names, from the project's folder, to see what the program says. A program that is not on the machine at all is MSBuild's own MSB6003. |
| `EQ4005` | A `.ttf` or `.otf` file under the app's `Assets` folder is not a face the SDK can ship. The SDK embeds every font file there and reads its family, its weights and its italic from the file itself, so a file it cannot read would ship a theme whose face falls back in silence. The message says why: a font collection (`.ttc`), a web font (WOFF or WOFF2), a file that is not a font, one whose tables run past its end, one whose family name cannot be written in a page (letters, digits, spaces and `-_.+` only), or one whose family has no letter or digit to name its member of the catalog by. | Ship each face as an OpenType file of its own, the `.ttf` or `.otf` a web font was made from, which every target's text engine reads. Remove what is not a font from `Assets`. |
| `EQ4006` | Two font files under `Assets` claim the same face: one family, overlapping weights and the same style, such as a static Regular and a variable file whose weight axis covers 400. Or two families whose names would make the same member of the catalog. | Keep one of the files. A variable font already sets every weight on its axis, so it replaces the static files of its style. |
| `EQ4007` | A `[assembly: GoogleFont(…)]` the build cannot read. The build reads it before the app compiles, from the syntax of the file it stands in, because the faces it fetches are embedded in that same compile: the family is a string literal, each weight a member of `FontWeight`, and `Italic` is `true` or `false`, written out where the attribute stands. The message names what it found instead, such as a constant declared elsewhere, a cast or a number, or an empty family. Or two declared families whose names share their letters and digits, such as `Roboto Mono` and `RobotoMono`, under which the build keeps their files. Or an alias of the attribute (`using GFont = …GoogleFontAttribute;`), which the build does not read: it knows the attribute by its own name. | Write the family and the weights out in the attribute: `[assembly: GoogleFont("Inter", FontWeight.Regular, FontWeight.Bold, Italic = true)]`. |
| `EQ4008` | Google Fonts cannot serve a family the app declares with `GoogleFont`: it has no family of that name, or not the weight or the italic asked for, which the message names. Or Google Fonts could not be reached, or failed to answer, while a file was still to fetch, one never pinned or a pinned one not yet under `obj`. | Write the family's name and its cuts as Google Fonts has them. For a provider out of reach, build again once the network is back: a build whose files are all fetched asks Google for nothing. |
| `EQ4009` | A pin in `fonts.lock.json` no longer holds. The file Google serves at a pinned URL is not the one pinned (its SHA-256 differs), Google no longer serves the pinned URL, or a cut was added to a family Google has replaced since its cuts were pinned, which would mix two of Google's versions in one family. Or the lock itself does not hold, and it is never read as fewer pins. The build stops rather than change the app's text without the app choosing it, and leaves the lock as it was. | Take the family out of `fonts.lock.json`, or delete the file to renew every family, and the next build pins the files Google serves now. Commit the new lock once the text has been looked at in them. A lock that does not hold is the SDK's to write: delete it. |
